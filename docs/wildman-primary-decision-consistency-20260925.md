# 以野人哥为主的辅助决策一致性改进方案

日期：2026-09-25。用户明确本系统仅辅助判断，不接真实交易。

## 依据和边界

用户提供的《保住本金是第一原则，慢就是快》为野人哥直播资料的粉丝整理稿。参考其中的先判市场周期、主线与龙头优先、风险与空仓纪律、预期和事实复核。文中的收益目标、仓位数值或描述性词语不自动成为新公式。保留现有 `backend/wildman/rules.py` 的周期、五步、角色、买点和风险规则；本次只统一这些判断在其他页面如何被引用和解释。

必须保留其它模型的原始事实、时间与结论作为可追溯证据。野人哥负责“主观点”；V4/V5、事件、ROCI、强势股作为补充/异议。绝不计算新的平均分，也不把建议写成真实下单能力。

## 一致性原则

1. 野人哥的周期、原五步参考结论、主线候选层及个股风险为主要解释。主线候选不等于五步确认；研究形态不等于模式内买点。
2. 数据错日、未来数据、来源失败或已确认的风险阻断必须明确显示“待核验/风险优先”。风险信息不能被高机会分抵消。V4的看法与野人哥不同时说明原因，不能把V4的判断偷偷当作野人哥结论。
3. 只比较同一决策日和已标注观察时间、周期的字段；不同天、不同期限返回“不可直接比较”及两个来源时间。
4. 对同一天同一仓位口径只呈现一个有效的参考上限。野人哥周期区间是模型观点；V4真值/数据质量产生的较低上限可收紧参考值，旁边写明来源和理由。V4意见为NO_TRADE且野人哥周期积极时优先提示“观点分歧，暂缓积极建议”，保留野人哥原观点与V4异议供人判断。
5. 同一题材的“事件达到雷达阈值”“主线候选”“五步核心确认”是不同状态，标题必须带对象和证据门槛。数据不能证明同一题材映射时标“关联待核验”，不得按名字强行合并。
6. 对股票先看否决事实：风险C区、硬风险、数据不足时，当前总提示不出现正向“买点”。原模型的形态名称可在详情里作为历史/研究事实保留，须写“风险阻断/仅供研究”。
7. 所有统一提示带 `decision_date`, `as_of`, `horizon`, `source`, `data_quality`, `reasons`。没有可靠比较数据时保留野人哥原结论并提示“暂无可比的其它意见”，不能拼接虚构数字。

## 最小实现范围

- 后端：新增纯函数辅助决策口径，不调用外部数据，也不覆盖原模型结果。使用已有市场工作台和野人哥的同日缓存形成只读解释层；提供日期、周期、野人哥主观点、V4补充观点/异议、有效参考仓位、数据与风险原因。缓存缺失或错日时以未知呈现，不将旧意见伪装成同日冲突。
- V4本页：LIMITED/FAIL真值门槛调整仓位时，同步 `strategy_selector.max_total_position_pct` 与展示；保留原始策略说明及真值降级原因。V5行动中心引用相同有效上限。
- 野人哥页：驾驶舱的题材徽标读取和主线雷达相同的 `candidate_discovery.status`，并列显示原五步结论。主观点首屏显示周期、主线、可比日期、风险及有效仓位，V4/V5为有来源的补充或异议。
- 强势股V2：风险C区/高风险时增加明确的有效买点阻断字段和页面风险优先说明；原始形态研究结果仍可查看。V1/个股决策如有硬风险只能显示研究/风险态。
- 事件雷达：`CONFIRMED`展示为“事件雷达确认”，明确不能代表主线五步确认；题材映射保留多对多与原来源。

## 验收场景

- V4真值 LIMITED 导致主上限25%、原策略上限40%时，所有总览和策略区只能看到有效参考上限25%，并展示“真值降级”原因。
- 野人哥主升20%~40%，V4同日NO_TRADE或因数据质量阻断时，界面仍保留野人哥周期结论，统一提示为分歧/暂缓积极建议，不能让两个模块同时给出互斥的最终参考仓位。
- 野人哥冰点0或≤5%而V4参考40%时，最终参考不超过5%，两边的原模型观点可追溯。
- 主线发现为watch/unknown而五步未通过时，野人哥驾驶舱不能标“主线候选”；候选发现为candidate且五步2/5时同时展示两层结论。
- 强势股风险C区且原形态字段写“一般买点”时，总提示风险优先，并把该字段限于研究详情。
- 事件状态CONFIRMED、五步主线未确认时，界面显示“事件雷达确认/主线未确认”。
- 任何错日、缺失、旧缓存或不同周期不提供假的统一结论。原五步全729个状态组合与受保护文件hash保持不变；单元测试、TypeScript检查、生产构建、桌面和390px页面验证通过。必要时先预览、后正式上线，再验真实接口与静态资源。
