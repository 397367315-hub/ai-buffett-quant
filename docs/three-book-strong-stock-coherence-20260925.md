# 三书强势股研究工作台改造方案

日期：2026-09-25。系统只辅助判断，不连接实际交易。

## 决策层级

野人哥市场周期及风险为跨模块总参考；强势股页面内部以《猎取强势股》的量时空、量价、A/B/C 区和卖出风险为个股结构基础。《暴涨大形态》识别结构阶段，《暴涨之星》识别星线及其前置和后续条件。书籍内容是规则依据；代码中的数值特征阈值若原书未明定，须标为系统量化代理，不能宣称为原书公式。

三书信号分别展示证据、反证、日期和来源。C 区、明确顶部或数据无法核验时，正向形态仍可保留为研究记录，但总提示不得升级为积极买点。缺少大形态或星线不自动否定《猎取强势股》的 A/B 结构候选；“三书共振”只在各自有可核验证据且同日时呈现。

## 页面链路

1. **总览**：市场/风险状态、野人哥主观点、三书研究口径和候选数量。
2. **板块线索**：使用已存板块走势、宽度、资金与生命周期识别观察方向。板块线索是系统市场数据的研究分组，不冒称三书自带的“核心主线”公式，也不等于野人哥五步确认。
3. **候选池**：复用全市场扫描和 V2.1 机会融合，逐只附《猎取强势股》区域/风险、大形态、星线的同日证据；未核验者留在初筛观察层，不进入三书核验候选。按板块/状态/风险筛选，点击进入个股查询。
4. **个股查询**：显示三书各自结论和理由、当前最强反证、下一观察点、失效条件、来源及截点；有效研究状态优先于旧模型的正向文字。
5. **复盘**：把候选当时的状态与后续 1/3/5 日结果分开，禁止事后信息回填当日判断。

## 当前代码事实和待修点

- `backend/services/strong_stock_v21.py` 已有市场、板块、全市场初筛和候选快照；但候选行的 `big_pattern_state`、`rising_star_state`、`volume_price_state`、`ma_state` 目前写为 `None`，所以现有池不是三书证据池。
- `backend/strong_stock_decision/service.py` 会持久化 V2 `StockSkillSignal` 和 `ThreeBooksConsensus`；候选池读取时必须按交易日与版本核验，不能将旧个股访问产生的信号混到今天。
- `frontend/app/strong-stock-decision/page.tsx` 将板块/机会桥接层放在个股长页面底部，缺少从板块线索到候选池再到个股的导航闭环。
- 原 V1 ACTION、V2 Shadow、V2.1 融合和野人哥总参考须分别标记来源，不强行合成一个买卖指令。

## 验收

- 三份扫描书籍各有规则映射与页码；原书未给数值时不得标注为书籍原阈值。
- 同日且本书 A/B 结构可信、无 C 区/顶部否决时，可以进入结构候选；仅有系统初筛、过期三书快照或缺失日线时仍是观察待核验。
- 大形态、星线可以提升研究解释力度，但不会越过《猎取强势股》的 C 区和跨模块野人哥风险总参考。顶部星线只能进入风险侧。
- 板块线索、候选池、个股查询能从同一个导航进入；候选可点到对应股票，手机 390px 不出现整页横向溢出。
- 回归原野人哥五步规则、强势股 V1/V2/V2.1 测试；真实接口校验三书证据日期和候选数量。
