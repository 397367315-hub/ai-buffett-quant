# 交易圆桌接入说明

## 范围与入口

- 独立入口 `/trading-roundtable`，导航按钮“交易圆桌”在新窗口打开。
- 原圆桌经典界面、圆桌讨论、总指挥与实验工作区保留。
- 共享宿主管理员登录、猫爪网关和 DeepSeek 配置；不另存共享 API 密钥。
- 各席输出并列，剑门环境参考仅作用于本席。研究候选不等于系统交易许可；原野人哥五步参考原则及三书规则不变。
- 系统只用于研究和模拟；交接包中尚未开放的实时提醒和订阅保持关闭。

## 目录

- `backend/roundtable_workspace`：从交接候选 rc-20261022-84ff309c13b8 引入的服务、契约和验收程序。
- `integrations/trading-roundtable/frontend`：圆桌 Vite 源码。
- `frontend/public/roundtable`：构建生成物，不进入 Git。
- `backend/services/roundtable_*.py`：共享供应商、持久化、私有资源及刷新任务。
- `backend/api/roundtable*_routes.py`：管理员鉴权、会话绑定、来源与 CSRF 校验。

原压缩包 SHA-256：`e35dd898f71434ebd856f43e098141e365939960f83b7034403a42fedc7d57c4`。
原工作区未被覆盖。

## 私有资料与配置

公开仓库只保存 AES-256-GCM 加密资料包，不提交原书、知识库明文、技能明文或密钥。

后端需设置 `ROUNDTABLE_ASSET_KEY`。生成与更新资料包：

```sh
.venv/bin/python scripts/package_roundtable_assets.py
```

此命令只输出文件位置、数量和校验信息，密钥留在本机私有凭据目录；部署时仅配置到后端环境变量。
后端的 `MEOZ_API_KEY` / `NUMCAT_API_KEY` 与 `DEEPSEEK_API_KEY` 沿用原系统。

## 数据与存储

- 经典漏斗通过“刷新数据”或“同步最新数据”提交后台任务，显示实际阶段，生成含创业板和仅主板两份结果。
- 130 日全市场输入按需读取；计算脚本采用列式输入，规则与数值计算保持不变。
- 大型计算和打包互斥，避免多个计算进程同时占用小规格实例。
- 服务端研究、快照、证据、会话、模型存档和 v1 模拟账本保存到现有数据库。
- 行情原件按内容 SHA 单独保存并复用，主状态只保存轻量检查点与文件清单，避免每次操作重复压缩历史行情。
- 浏览器只保存公开圆桌 session id；内部 Cookie 留在后端。每个 API 请求同时验证宿主登录。
- 用户另外填写的模型密钥经加密保存，共享宿主密钥不写入圆桌存档。
- 经典个人池沿用独立的本机浏览器存储，页面明确标注；实验 v1 模拟账本使用服务端存储。两者不互相覆盖。
- 无数据保持缺失或错误；生产不自动回退演示数据。日线/收盘数据不标作逐笔实时。

## 构建与验收

在 `frontend/` 执行：

```sh
npm run build:roundtable
npm run build
```

Netlify 配置已自动按以上顺序构建。后端新增依赖 `cryptography` 和 `ijson`。

主机集成测试位于 `backend/tests/test_roundtable_*.py`；原业务验收位于
`backend/roundtable_workspace/tests` 和 `acceptance/`。原验收 AC-029 的 freeze 成功码已按 OpenAPI 契约统一为 200。
缺少历史归档或浏览器环境的原测试会明确标记阻断/未运行，不能当作通过。

上线核验需同时检查：真实猫爪返回、DeepSeek 请求、13 席注册与规则任务、候选抽屉、圆桌/总指挥、写操作、刷新后持久化，以及桌面和 390px 布局。
本次本地真实样本截至 2026-10-21 收盘：经典样本 4599 只，合格池 2061 只，去重研究候选 81 只。

## 发布与回滚

部署到现有 Render 后端和 Netlify 项目，不新增付费服务。
数据库改动只新增圆桌专用表，不覆盖原系统数据。回滚代码时保留圆桌表，后续恢复版本可继续读取。
发布必须验证实际服务版本与业务数据；单独构建成功或 `/health` 返回成功不作为全部验收。
